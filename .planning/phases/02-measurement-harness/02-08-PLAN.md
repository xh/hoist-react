<objective>
Close gap 3 from 02-VERIFICATION.md - the heap-attribution methodology defects, both confirmed live
WITH the documented Chrome flags active. Two defects:

(1) Inverted/within-iteration total. `runIterationAsync` captures `baselineHeap = heapNow()` BEFORE
`forceGcAndSettleAsync`, then `attributeHeap` reads `heapNow()` AFTER the GC. So the "total" measures
how much the forced GC freed and goes NEGATIVE (observed -28.2 MB). There is no clean empty-pipeline
baseline because the caller pre-loads the snapshot before the harness runs.

(2) Noise-swamped per-layer. Per-layer value = recordCount x a single 1000-row calibration diff,
which is below the tens-of-MB GC/heap variance against a ~366 MB live heap, so every owned layer
reads 0 even with the flags. A negative->0 floor is already committed (ba4b48b21) as a stopgap, but
the underlying attribution is still untrustworthy.

The fixes (all must respect the documented forced-GC / steady-state protocol and the
`--js-flags=--expose-gc` + `--enable-precise-memory-info` flags):
- Capture a clean post-GC EMPTY-pipeline baseline BEFORE the snapshot loads, and compute total
  retained heap against that fixed reference. This requires a contract change with a TRULY-EMPTY
  pipeline hook. CRITICAL - the existing injected `clearAsync()` callback does NOT empty the
  pipeline: in the live caller (`../toolbox/.../DataLabModel.ts:302-304`) it is wired to
  `async () => { await adapter.loadSnapshotAsync(snapshotRows); }`, which RELOADS the full snapshot.
  Differencing against a snapshot-loaded heap would make `totalHeapDelta ~= 0`, not the positive
  retained figure gap 3 requires. The calibration teardown ends in that same snapshot-reloading
  clear, so it is NOT a viable empty source either. `disposeAsync()` is too destructive (it nulls
  the cube/view/gridModel, losing the grid the bridge measurement needs). The pinned mechanism: add
  a `clearPipelineAsync()` to `BaselineAdapter` that calls `Cube.clearAsync()` - confirmed via MCP to
  "Clear any/all data and info from this Cube" and to re-aggregate connected Views asynchronously, so
  the grid store empties - WITHOUT nulling the pipeline. The harness empties via this hook, captures
  the baseline, then RELOADS the snapshot via a new injected `reloadSnapshotAsync()` provider hook
  (the caller already holds the fetched `snapshotRows`). Toolbox `DataLabModel.ts` is IN SCOPE for
  this plan to wire both hooks.
- Sturdier per-layer calibration: N=50000 (10x the 5000-leaf default scenario, so the calibration
  load itself moves tens of MB and clears the documented tens-of-MB variance) with repeats=5 and
  median-of-repeats on a dedicated empty pipeline (run the load-N/clear cycle 5 times and take the
  median per-record bytes), so the signal clears the noise floor. The committed floor-at-0
  (ba4b48b21) means an under-resolved layer silently reads 0 again - the exact failure being closed -
  so the calibration load MUST move a measurable, tens-of-MB delta, not a "sane larger N".
- Re-verify live under the flags: positive total, non-negative/plausible layers, remainder >= 0.

This plan depends on 02-07: the corrected tree shape changes the cube/aggregate/grid record counts
that feed `attributeHeap`, and 02-07 restructured `runIterationAsync`, so heap rework lands on top
of those changes.

Purpose: make heap attribution trustworthy (HARN-04) under the documented protocol (HARN-05).
Output: corrected `HeapAttribution.ts`, `MeasurementHarness.ts`, README protocol doc, verified live.
