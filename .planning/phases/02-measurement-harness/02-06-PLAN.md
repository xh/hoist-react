<objective>
Build the interactive harness UI as a Toolbox example app: a scenario picker (configs persisted via
Hoist ViewManager), run controls that drive the framework's `MeasurementHarness` over the chosen
transport, an on-screen scorecard, and a side-by-side comparison of saved runs. Wire the client ingest
adapters that pull the out-of-process Grails data (02-02) into the harness over both HTTP and WebSocket.
Register the example as a standalone, routable Toolbox app the same way Portfolio is registered. Finally,
document the harness in a framework README.

Purpose: Locked decisions - the interactive UI lives in Toolbox (public, demonstrable), configs are
named ViewManager JsonBlobs ("profiles and update patterns are data, not code"), comparison is a
first-class feature driven from saved runs, and each run is persisted + stamped with env metadata. This
is the last assembly step that makes the harness usable and demonstrably reusable (HARN-06). It carries a
human-verify checkpoint because the interactive run experience and the on-screen scorecard need a human
to confirm in a real browser with the GC/precise-memory flags.
Output: A `datalab` example app in Toolbox (registered + routable) + a `data/measure/README.md`.
</objective>

The Toolbox example-registration mechanism (confirmed by inspection - implement to match):
1. Each example is a STANDALONE app under `src/examples/{name}/` with its own `AppModel.ts` (extends
   `BaseAppModel`) and `AppComponent.ts` (hoistCmp wrapping an appBar + the inner panel).
2. `src/apps/{name}.ts` is the webpack entry point - one file per app, auto-discovered by
   `@xh/hoist-dev-utils/configureWebpack`, producing a bundle served at `/{name}/`. It imports
   `../Bootstrap` and calls `XH.renderApp({clientAppCode, clientAppName, componentClass, modelClass, ...})`.
3. `src/desktop/tabs/examples/ExamplesTabModel.ts` holds an `examples[]` array; each entry
   `{title, icon, path, srcPath, text}` adds the tile and is iframed by ExamplesTab at
   `${origin}/${path}/`. Add a `datalab` entry (path/srcPath `'datalab'`).
So `DataLabModel`/`DataLabPanel` are the INNER content (mirroring `PortfolioModel`/`PortfolioPanel`), and
the new `AppModel`/`AppComponent`/`apps/datalab.ts`/`ExamplesTabModel` entry are the registration wrapper.
