<objective>
Build the boundary-instrumentation layer of the measurement core: helpers that wrap the six Phase-1
boundaries with Hoist's `runner().span()` for trace structure/correlation while capturing the
load-bearing elapsed numbers with `performance.now()`, and that split Boundary 5 into compute
(genTransaction) vs bridge (applyTransaction) vs deferred render. Plus a null-scenario overhead probe.

boundaries (not per-micro-op) with bounded, documented overhead. HARN-05 requires the compute-vs-bridge
split. The critical research finding: Hoist `Span` timing is `Date.now()` (ms) - too coarse for sub-ms
compute - so the harness must time with `performance.now()` and use spans only for structure/correlation.

</objective>

  <name>Task 1: Generic boundary timing helper (HARN-03)</name>
  <files>data/measure/BoundaryInstrumentation.ts</files>
  <action>
Create `data/measure/BoundaryInstrumentation.ts` with the standard Hoist file header.

Implement a generic async helper `measureBoundary<T>(host: HoistBase, name: string, fn: () => Promise<T> | T): Promise<{result: T; elapsedMs: number}>` that:
- Opens a span via `host.runner().span(name).run(async span => {...})` for trace STRUCTURE/correlation
  only (this is where it bubbles into Hoist's OTel/TraceService per HARN-03).
- Brackets `fn()` with `const t0 = performance.now()` ... `const elapsedMs = performance.now() - t0`.
- Attaches the elapsed value to the span as a tag (e.g. `span.setTag('xhDataLab.elapsedMs', elapsedMs)`),
  so the precise number rides along with the span but the span's own Date.now() duration is NOT used.
- Returns both the fn result and the precise elapsedMs.

Confirm the exact runner/span API via `hoist-read-doc docs/telemetry` and `hoist-get-members Span`
before writing - use `runner().span()`, NOT the deprecated `withSpan()`. Use a `'xhDataLab.'` span/tag
name prefix consistently.

Add a top-of-file JSDoc comment listing the six Phase-1 boundaries this module instruments (cube ingest;
cube->view push; View.result ref write; Store/_filtered rebuild; grid dataReaction/genTransaction/
applyTransaction; heap layers - heap handled in 02-04) and stating the rule: spans for structure,
performance.now() for the number. Comment WHY (Span is Date.now()/ms - cite Pitfall 1).
  </action>
  <verify>`npx tsc --noEmit` passes; `grep -n "performance.now()" data/measure/BoundaryInstrumentation.ts` matches; `grep -n "runner()" data/measure/BoundaryInstrumentation.ts` matches; no `Date.now(`/`.duration` used for the measured number.</verify>
  <done>measureBoundary wraps a fn in a runner().span() and returns precise performance.now() elapsed, attaching it as a span tag; the six boundaries are documented; the span-vs-timer rationale is commented.</done>

- `t0 = performance.now()`; `const txn = genTransaction()` (Hoist-side COMPUTE); `t1 = performance.now()`.

  return the three values.
